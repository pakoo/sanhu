一、先回答你的问题

✅

现在是纯手动。自动刷新能做，回放也能做 —— 但各有一个前置条件。

现状：前端完全不自动刷新 —— 只有切到 Tab 时懒加载一次，之后要看新数据只能点「刷新」。 但后端其实一直在动：调度器在交易时段每 30 分钟抓一次并落库。 也就是说数据是新的，只是页面不知道。

自动刷新的前置条件：后端 BuildBoard 目前每次 API 调用都回源打东财，没有 TTL 缓存。 前端要是每 60 秒刷一次，就是每小时 60 个东财请求 —— 正好是限流的成因。 必须先补缓存，否则自动刷新等于给自己挖坑（见第二节）。

回放的前置条件：回放能覆盖多少板块，完全取决于存了多少板块的分时。 现在只存 Top20，而且这个数字不是随便定的 —— 每多存一个板块就多一个东财请求（见第四节）。

二、加自动刷新之前，必须先修的一件事

前置后端没有 TTL 缓存，每次请求都回源

现在的 BuildBoard 是这样的：

func BuildBoard(db, kind, dedup) *Board {
    rows, err := fetchRank(kind)      ← 无条件回源，每次 API 调用都真打东财
    if err == nil { ... return b }
    // 只有失败时才用缓存
}

内存缓存只在抓取失败时当兜底，不是「N 分钟内直接复用」。 所以「前端每 60 秒自动刷新」在当前实现下 = 每小时 60 个东财请求， 而项目记录里 200 个请求就会被限流。这是自动刷新方案的硬前置。

改法：给 BuildBoard 加 TTL —— 缓存在 N 分钟内直接返回，不回源。 这样前端爱怎么轮询都行，东财请求量由 TTL 决定，与前端刷新频率彻底解耦。 TTL 取多少见 Q1；改动量约 0.2 人日。

顺带解耦之后，自动刷新几乎零成本

加了 TTL 之后，前端轮询打的是本地内存，不产生任何外部请求。 所以「多久刷一次页面」和「多久打一次东财」变成两个独立的旋钮： 前端可以 30 秒刷一次让界面显得活，而东财那边仍然是 30 分钟一次。

三、自动刷新怎么做

方案前端行为后端 TTL东财请求量体感
A 保持手动不轮询不需要仅调度器 13 次/天 要看新数据得点刷新。符合本项目「每天只看 1–2 次」的既有定位
B 温和轮询停留在 Tab 时每 60 秒拉一次5 分钟≤ 12 次/小时 最多滞后 5 分钟，界面自己会更新，不用管它
C 准实时每 15 秒拉一次1 分钟≤ 60 次/小时 滞后 <1 分钟，但东财请求量接近限流量级，收益很低 —— 板块资金流不是盯盘用的
必做三个方案都要遵守的规矩

① 只在交易时段轮询。收盘后数据不再变，继续轮询纯属浪费 —— 用已有的 InTradingSession 判断。
② 页面不可见时暂停。用 document.visibilityState，切到别的 Tab 或最小化就停，回来再续。
③ 刷新时不能闪。整块 innerHTML 重绘会让用户正在看的行跳掉；要做成只更新数值和条宽。

四、回放能做成什么样，由数据决定

先说清楚数据边界，因为它直接决定了回放的形态 —— 这不是设计取舍，是硬约束。

已经有的：每天收盘后留档 Top20 个板块的分时曲线，每个 240 个分钟点（09:31→15:00）。 这些点是当日累计值，所以回放时数值会从 0 一路长起来 —— 天然就是「资金逐步进场」的动画，不用额外处理。

没有的：全部 496 个板块的分钟级数据。原因是抓取成本：分时接口一次只能取一个板块， 要覆盖 496 个就是 496 个请求。而且必须串行 + 间隔（现在是 1.5 秒/个）， 496 个要跑 12 分钟以上，还极可能触发限流。

所以回放的可选范围是「留档多少个板块」，这是个成本换覆盖的旋钮：

留档范围每日新增请求收盘任务耗时每年存储回放能看到什么
Top20（现状）20约 30 秒约 50 MB当日最热的 20 个。够做曲线赛跑，热力图会显得稀疏
Top5050约 75 秒约 125 MB热力图有内容了，主要板块基本都在
Top100100约 2.5 分钟约 250 MB接近完整市场图景，但请求量已是现在的 5 倍
全部 496496约 12 分钟约 1.2 GB不可行 —— 极可能触发限流，且没人会看长尾板块的回放
注意回放只能回放「已经存过的日子」

东财的分时接口只提供当日，历史分时拿不到。所以功能上线前的日子永远补不回来 —— 回放从上线那天开始才有得看。这跟历史日线是同一个道理，也再次说明早点开始落库是有价值的。

六、热力图回放的一个真问题：每帧要不要重排

这个问题只在 Q3 选了 B 或「都做」时才需要拍。但它影响很大 —— 选错了回放会看得人眼晕。

甲顺序固定（按收盘排名布局）
色块位置全程不动，只有面积和颜色在变。
  • 优点：眼睛能锁定某一块盯着看它怎么变，不晕
  • 缺点：用了「上帝视角」—— 10:00 时的排位其实是收盘才知道的
乙每帧重排（按当前时刻排名）
每一帧都按当下的净额重新布局，位置一直在换。
  • 优点：如实反映「此刻的格局」，没有未来信息
  • 缺点：色块乱跳，盯不住任何一块，回放变成万花筒

七、回放控制条

C1播放控制 按真实交易时段刻度
进度轴按 A 股交易时段刻度，午休 11:30–13:00 画成灰段并直接跳过 —— 那 90 分钟没有数据， 不跳的话进度条会卡在原地不动，看起来像卡死了。

默认速度 4×：240 分钟按 1× 放要 4 分钟，太久；4× 约 1 分钟，正好是一杯咖啡的注意力。 16× 用来快速扫一遍找异动时点。

回放哪一天：默认最近一个有留档的交易日，可以选日期。 没有留档的日子在日期选择器里置灰，并注明「该功能上线前的日期没有数据」。

一、问题是什么

你指着选基页那两个按钮说「用户看了根本不知道怎么玩」。我把全站四个 AI 入口逐个拆开看了， 问题比按钮文案严重得多 —— 三个入口的导出内容是坏的，一个入口的说明是缺的。

这个功能本该是产品的核心卖点。项目设计原则里写着「无后端 AI：不调用任何 LLM API， AI 功能通过生成 Prompt 让用户自己去问」。也就是说：工具的价值在于把你的真实持仓整理成 一份 AI 看得懂、且只有这个工具才拿得出来的结构化数据。这件事现在没做到。

为什么会这样：赛道分析的 prompt 模板是 Python 时代精心写的（模板里那段 philosophy_check 甚至自我要求「不只是『请分析 X』式的空问题」）， 渲染逻辑在 backend/ai_prompts.py 里 —— 有构建持股表、peer 对比表、 PE 百分位、择时信号的完整代码。
Go 重写时，这个接口变成了一行 ReadFile(prompts/theme_analysis.md) 原样返回， 渲染整块没实现。选基的导出则是直接把 session 缓存的 JSON 打出来。
这是 Go 重写漏掉的第五处同类问题（前四处：持仓解析器、行业抓取、调仓建议契约、选基链路）。
不在本轮范围：不接入任何 LLM API（这是项目原则，不改）； 选基候选池的数据质量问题（另有决策）；缺口口径本身（另有决策）。

六、AI 答完之后呢（闭环，E4）

这是目前完全没有的一段：用户拿到 AI 的分析后，工具里没有任何位置承接它。 分析结果留在 Claude 的对话里，下次打开工具就找不到了 —— 而这个工具的定位恰恰是「决策助手」，决策依据理应能留档。

Q5待你决策
AI 的回答要不要能贴回工具存档？
架构变更提醒：要存的话需要新增一张表（或复用 decisions 表加字段）存「数据快照 + AI 结论 + 时间」。这是本稿唯一涉及落库的改动。不做的代价：AI 分析变成一次性消耗品，工具无法成为决策档案。

七、涉及的改动与架构变更

后端：
① GetFundAIThemePrompt 补渲染 —— 现在是 ReadFile 原样返回， 占位符 {seed_name} 全未替换，且把 484 字开发者注释一起返回给用户。 参照 Python 的 render_theme_analysis_prompt（含持股表 / peer 对比 / PE 百分位 / 择时信号）。
② ExportSelectorSession 重写 —— 现在输出 #Selector Session xxx + 原始 JSON。
③ GetAIContext 增强 —— 现在只有数据没有指令，分类是英文 bond/equity。
④ 新增统一的 prompt 渲染层，四个入口共用（数字格式化、中文分类名、markdown 表格）。

架构变更（Gate 要求点明）：
· 若 Q5 选「做」→ 新增落库：存数据快照 + AI 结论（新表或 decisions 加字段），需你确认。
· 若 Q5 选「先不做」→ 不涉及任何架构变更，纯改渲染与前端。
· 若 Q3 选「自动打开」→ 工具会主动打开外部网站（claude.ai），行为写在按钮文字里。

隐私边界（无论怎么选都要守）：提示词里不含持仓金额、账户信息，只含占比与分类。 预览弹窗里明确写出这一点 —— 用户敢用的前提是知道发出去的是什么。

八、本稿不涉及分享

sanhu 是本地运行的桌面 Web 工具，不是微信小程序，没有分享卡片这一层； 且本稿处理的是用户真实持仓数据，本就不应有对外分享入口。 写在这里是为了把「漏了」和「刻意不做」区分开。

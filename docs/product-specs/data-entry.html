一、背景与调性

先澄清一件事：「手动录入」已经是默认 Tab —— importTabManual 在 index.html:850 默认高亮，截图导入是第二个 Tab。所以本轮不是从零做手动录入， 而是决定把它推到多前面、以及补上它现在缺的那半截。

真正的痛点（实测，不是猜）：
① 新用户落地是一片空白。全新安装打开首页：四个 0、一个灰甜甜圈、空柱状图， 持仓明细表<tbody>一行都没有、连一句「还没有持仓」都不写。 唯一的入口「更新持仓」按钮在首屏之下。
② 录进去的基金大概率显示 0 元。内置数据只有 11 只基金，录入库里没有的基金时， import.go:162 只写一行 INSERT OR IGNORE INTO funds (code, name) —— 没有 fund_type、没有净值。 于是 shares = 金额 / 净值 算不出来只能落 0，持仓市值 = 净值 × 份额 = 0。

实测：在全新实例里手工录入「110022 易方达消费行业，持有金额 50000，收益 3000」，得到的是 ——
名称: "110022"　市值: 0　成本: 47000　净值: 470000000
名称显示成代码；5 万块市值直接变 0；净值那个 4.7 亿是兜底公式 成本 / max(份额, 0.0001) 在份额为 0 时算出来的。总资产 0，收益率 −100%。
这不是边缘情况 —— 用户的基金有九成不在那 11 只里。

调性：工具感 / 克制 / 不劝诱交易。录入是「把你已经买的东西抄进来」，不是开户， 语气要像记账本，不像券商 App。
不在本轮范围：交易流水（买入/卖出记录）的录入改造、持仓透视、OCR 引擎更换、基金搜索能力。

Q1待你决策已确认并落地 · dc51f24
新用户打开是一片 0，引导做成哪种形态？
三个方案的差别是打扰程度：横幅最轻但容易被忽略，接管内容区把「没数据」这件事说清楚，自动弹窗转化最高但有被当成弹窗广告的风险。不做的代价：新用户看到四个 0 和一个灰圈，不知道下一步该干什么，大概率直接关掉。

四、录进去却显示 0 元（E4 · 本稿最关键的一处）

这不是 UI 问题，是数据补齐时机没定。用户录入的是「代码 + 金额」， 但系统要算市值必须有净值，要分类必须有fund_type —— 这两样都得去东财抓。 现在一次都没抓，直接落库，于是市值为 0。
抓一只基金的档案 + 近 3 年净值，实测约 1～3 秒；录 8 只就是 10～25 秒。这段时间怎么处理，是下面这道题。

【现状】 用户打开 → 空首页（无引导）→ 自己找到「更新持仓」→ 填代码+金额 → 确认 │ ▼ ImportCommit：只写 funds(code,name)，不抓任何数据 │ ┌────────────────────────┴────────────────────────┐ ▼ ▼ 基金在内置的 11 只里 基金不在内置数据里（九成情况） 有净值 → 份额算得出 无净值 → 份额=0 → 市值=0 显示正常 名称显示成代码、净值 4.7 亿、总资产 0 【目标】 用户打开 → E1 空态引导 → 点「开始录入」→ 填代码 │ ▼ Q2 决定的抓取时机（校验/同步/后台） │ ▼ 档案 + 净值入库 → 份额算得出 → 显示正常 │ ▼ 抓不到时走 Q3 的兜底口径（不再显示 0）
涉及的架构变更（Gate 要求必须点明）：
① ImportCommit 新增对外抓取调用 —— 接口耗时从毫秒级变秒级，需要考虑超时与失败提示；
② 若选 Q2-乙，需新增后台任务队列 + 进度查询接口（比照现有 /api/holdings/refresh/status 的做法）；
③ 若选 Q1-丙，需要持久化「已关闭过引导」状态 —— 存 localStorage（换浏览器会重弹）还是 user_settings 表（跟着数据库走）需一并确认；
④ 不新增数据表，不改动 holdings 表结构。

七、分享设计

本稿不涉及分享。理由：sanhu 是本地运行的桌面 Web 工具（localhost），不是微信小程序， 没有分享卡片这一层；且本轮改的是录入流程，涉及用户真实持仓金额， 本就不应该有任何对外分享入口。
这里明确写出来，是为了把「漏写」和「刻意不做」区分开。

八、图片素材需求

本轮不需要出图，全部用 CSS 画。
空态引导里的那个图形（E1-乙 中的圆角虚线方块）用 CSS 画一个占位框即可 —— 与现有前端风格（纯 CSS + ECharts，无图片资源）保持一致，也避免给单文件二进制再塞图片资源。
确认后如果你想要一个空态插画，再单开规格：尺寸 240×180、PNG 透明底、 风格与主色 #5b5bd6 协调；不画任何基金公司 / 支付宝的 logo 或界面截图，避免侵权。
